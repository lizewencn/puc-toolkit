# APP 业务页签设计

## 目标

在现有 PUC Toolkit 主窗口中新增一级“APP 业务”页签，保留原有“PUC 配置”工作流，并为 APP 登录、在线状态监控和批量创建群提供统一入口。

## 界面结构

主窗口使用一级 TabControl：

- “PUC 配置”：承载当前环境选择、操作选择、输入、执行和结果区域，行为保持不变。
- “APP 业务”：承载 APP 登录和群组批处理。

APP 页签包括：

1. 登录区：服务器环境下拉框、账号、密码、IMEI/SN（或默认设备标识）、登录和停止按钮。服务器选择复用 PUC 配置页的环境数据和“新增环境”流程。
2. 状态区：连接状态、当前账号、APP PUC ID、最近事件和错误信息。
3. 批量建群区：成员账号与 APP PUC ID、群数量、启动按钮、进度和结果表格。

## 服务器选择与默认值

APP 登录服务器采用与 PUC 配置相同的环境下拉选择和新增环境方式。APP 页签默认选中当前 PUC 配置环境，并使用该环境的地址/IP：

- 环境切换或刷新后，APP 下拉框同步可用环境列表，并在当前选择仍为自动跟随时同步选中项；
- 通过“新增环境”创建的环境同时可被 PUC 配置和 APP 业务选择；
- 允许在当前环境基础上编辑实际登录地址/IP，编辑后标记为手动覆盖，不被环境刷新覆盖；
- 用户恢复“跟随当前环境”后可重新自动同步；
- 登录前校验为合法 HTTP/HTTPS 地址，并沿用 `app_puc_login` 的 TLS 校验规则。

## 运行与状态

- PowerShell UI 调用现有 Python 包，不重复实现 PUC 协议。
- `PucLoginClient` 在后台线程运行，事件通过安全的 UI 调度方式更新控件。
- `connecting`、`token_acquired`、`websocket_connected`、`login_success`、`disconnected`、`reconnecting`、`error`、`stopped` 映射到可读状态。
- 只有登录成功且会话在线时，批量建群按钮可用。
- 停止登录、断线或切换账号时，禁止新建群请求；进行中的批处理按服务层结果标记会话不可用。
- 密码、Token、Authorization 不显示在事件日志或结果中。

## 批量建群

调用 `AppPucGroupBatchService`：

- 校验群数量和成员输入，自动补充群主并去重；
- 使用临时群名创建，再按服务端时间戳重命名；
- 逐项报告创建、重命名、失败和会话不可用进度；
- 在结果表格中显示索引、群 ID、最终群名、创建码、重命名码和状态。

## 测试与验收

- 保留现有 PUC 配置 UI 自检结果。
- 增加主窗体 UI 自检：一级页签名称、APP 环境下拉与新增环境联动、服务器默认值和手动覆盖规则、登录状态控件及批量按钮启用条件。
- 运行 `app_puc_login` 现有测试，并补充 APP 页签桥接/状态映射的可测试逻辑。
- 手工验收：环境切换更新默认服务器、手动修改保持不变、登录成功显示在线、断线显示重连/离线、批量结果持续刷新。
