# 仓库版本包更新

GUI 标题栏右侧的下载图标用于更新仓库下的全部版本包，悬停提示为【更新版本包】。版本基准是 GitHub 仓库指定分支的最新 commit，不再分别查询某个 Skill 子目录。只有 `%LOCALAPPDATA%\puc-config\update-state.json` 中保存的仓库 commit ID 与远端仓库 commit ID 不一致时才执行更新；两者一致时不写文件，并明确提示仓库下全部版本包已是最新版本。

下载仓库快照时，在校验 GitHub 仓库地址和 commit ID 后直接访问 GitHub 归档域名，不能依赖 `zipball` 接口的 HTTP 302 跳转，因为共享 PUC HTTP 传输会拒绝非 2xx 响应。快照中只将顶层目录名合法且包含 `SKILL.md` 或 `scripts` 目录的目录识别为可安装包。所有包安装到当前 `puc-config` 的同级目录；已存在的包整体替换，不存在的包新增安装。`docs` 等不符合规则的目录不得写入全局 Skill 根目录。

GUI 下载按钮通过兼容入口自动调用同级 `puc-toolkit-updater`。前台阶段只下载、发现、校验并暂存全部包，不修改当前安装目录；完成后 GUI 自动启动暂存目录中的独立 Worker 并关闭自身。Worker 只等待该 GUI PID 退出，不扫描或关闭其他进程，然后事务替换包括 updater 自身在内的全部包并自动重启 GUI。

更新事务先备份所有现有目标，复制并校验每个包，最后写入仓库级 commit、更新时间和包清单。任一包复制、校验或状态写入失败时，删除本次新增内容并恢复所有旧包，不能留下混合版本。成功或回滚后都写入一次性 `update-result.json` 并重新启动 GUI，由执行摘要展示最终结果。状态文件保留旧字段以兼容历史数据，但新的版本判断和上次更新时间均优先读取 `repository` 节点。

更新只修改全局 Skill 根目录下由仓库管理的包，不覆盖用户配置、令牌、运行时状态或验证码文件。暂存完成后 GUI 自动退出，最终更新或回滚完成后由独立 Worker 自动启动 `Start-PucConfigTool.vbs`，不再要求用户手工重启。
